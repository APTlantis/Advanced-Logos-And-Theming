# Aptlantis Palette Transformer 1.0

Adapt a canonical logo-derived TOML palette into smaller or larger target palettes. Includes the supplied Zig dark palette and generated examples for every profile. This is stage two of the pipeline: application-native theme exporters remain a separate stage.

## Windows setup

Requires Python 3.11 or newer. From the extracted folder:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\Transform-Palette.ps1 -InputPalette .\examples\apt-zig-dark-palette.toml -Python .\.venv\Scripts\python.exe
```

Or call Python directly:

```powershell
.\.venv\Scripts\python.exe .\palette_transformer.py .\examples\apt-zig-dark-palette.toml --profile jetbrains --profiles .\profiles.toml --output .\output
.\.venv\Scripts\python.exe .\palette_transformer.py .\examples\apt-zig-dark-palette.toml --profile website --count 120 --output .\output
```

All eight profiles are generated by default. `--count` overrides one profile; `--profiles` loads customizable budgets, surface depth and minimum OKLab distance. The PowerShell wrapper supports the built-in profiles and count overrides; call Python directly to use a custom configuration file.

## Outputs

Each profile folder contains:

- `palette.toml`: grouped colors, role mappings, source hash and transformation metadata. Derived colors include their source, requested OKLCH, lightness delta, chroma scale, purpose and gamut mapping flag.
- `swatch.png`: labeled color preview distinguishing canonical and derived entries.
- `validation.json`: declared text/syntax and border contrast checks, close-color review items and limitations.
- `manifest.json`: retained, added and omitted colors plus every role remap and its perceptual distance.

The input file is read-only. The same bytes and options produce identical outputs. Output profile folders are overwritten on rerun; choose a fresh output directory to retain revisions.

## Color behavior

Input schema follows `palette.<family>.<id>`, with color values in inline tables or ordinary TOML tables. Roles are `roles.<group>.<role> = "color_id"`.

OKLCH takes precedence, followed by six-digit hex, followed by integer RGB (0–255). Hex/RGB inputs are converted to OKLCH internally. Numeric L is 0–1, C is nonnegative, H is degrees. OKLCH is converted to sRGB using chroma reduction at fixed lightness and hue when outside gamut. Serialized OKLCH reflects the final quantized RGB. A conflicting hex value is reported. Original source metadata remains in the untouched input file; output values are normalized representations.

Reduction first retains app/editor backgrounds and primary text. Terminal reduction additionally retains all supplied terminal slots. Remaining colors use greedy farthest-point selection in OKLab. Omitted role references map to the nearest retained color, with a recorded distance. An impossible anchor budget fails rather than dropping mandatory anchors.

Expansion retains all canonical entries, then adds nested surfaces and hover/pressed/subdued accent, text and syntax variants. Further bounded family variants fill larger budgets. Near-duplicate candidates are skipped; generated variants do not invent new semantic hues. Dark surfaces move lighter; light surfaces move darker. Set `theme.variant = "light"` for a light source palette. Supply appropriate light-palette role mappings; the tool does not convert a dark palette into a complete light theme.

Derived IDs are exposed in `roles.derived` for the next exporter stage. They are candidate state tokens, not guaranteed contrast-safe assignments to every component. Canonical success/warning and ANSI hue assignments are intentionally retained. Bright ANSI slots are not synthesized or exported in this stage.

## Validation and interpretation

Contrast uses the WCAG relative-luminance ratio. APCA is explicitly not computed. Checks cover declared text and syntax against `app_bg`, and declared subtle/strong borders against `app_bg`; actual component backgrounds, hover states and overlays require exporter-level checking. Applying a 3:1 check to a subtle decorative border is a review policy, not a claim that every decorative border requires it.

A near-color distance below 0.02 is a review item. Same-family pairs are marked so related colors can be distinguished from unintended collisions. The generation filter defaults to 0.012 OKLab distance. This is a heuristic, not proof that all users can distinguish a pair; color-vision-deficiency simulations are not implemented. Reports include both named and unique hex counts. Counts can fall below the requested budget if distinct candidates run out.

In this Zig source, muted text is 3.495:1 against app background and the strong border is 1.569:1. The transformer reports these inherited issues and preserves their mappings. `--strict` writes all outputs and exits 2 when any checked contrast pair fails. Exit 1 indicates invalid input or another processing error; exit 0 means generation completed, even if the report contains review findings.

## Verification

```powershell
python -m unittest discover -s tests -v
```

Seven tests cover standard color roundtrips and 21:1 black/white contrast, all profile sizes and valid roles, retained canonical colors and terminal anchors, gamut mapping, hex/RGB fallback and invalid references, light surface direction, byte-identical regeneration, output TOML reload and impossible reduction budgets. The Windows PowerShell wrapper has not been executed in the Linux build environment.

## Integration

Stage 1: logo extraction → canonical palette and swatch.

Stage 2: this tool → profile palette, swatch, validation and provenance.

Stage 3: native exporters → application properties and validation of final component pairings.

Only Pillow is an external runtime dependency, used for PNG output. Color conversions, TOML reading, validation and manifest generation use Python's standard library.
